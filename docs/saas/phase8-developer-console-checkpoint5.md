## 2. Implemented Capabilities

### 2.1 Webhooks Tab (`WebhookManagementTab.tsx`)
Connected to the existing organization webhook API (`/api/organizations/:orgId/webhooks`):
1. **Endpoint Registration & Listing:**
   - Lists all registered webhook endpoints for the selected organization.
   - Shows public endpoint URL, description, subscribed event badges (`room.created`, `room.ended`, `participant.joined`, `participant.left`, `recording.ready`), active status, and masked secret prefix (`whsec_...••••••••`).
   - Supports creating new endpoints via `POST /api/organizations/:orgId/webhooks`.
2. **One-Time Secret Reveal Modal (`WebhookSecretRevealModal.tsx`):**
   - When a new endpoint is registered, the raw signing secret generated by `webhookService.ts` is displayed **exactly once** in a secure modal.
   - Displays clear warning that the secret cannot be retrieved again from the server.
   - Provides a one-click copy button and signature verification guidance (`X-Mathsy-Signature: t=...,v1=hmac_sha256`).
3. **Endpoint Editing & Deletion:**
   - **Edit:** Modifies endpoint URL, description, subscribed events, and active status toggle (`PATCH /api/organizations/:orgId/webhooks/:endpointId`).
   - **Delete:** Safely revokes and removes the webhook endpoint with confirmation prompt (`DELETE /api/organizations/:orgId/webhooks/:endpointId`).
4. **Delivery History & Status Inspection (`WebhookDeliveriesModal.tsx`):**
   - Queries `GET /api/organizations/:orgId/webhooks/:endpointId/deliveries` (limit 50).
   - Displays event type, delivery timestamp, attempt count, HTTP response status badge (`200 OK`, `404`, `500`), and error messages.
   - Interactive accordion view revealing the exact dispatched JSON payload and response body returned by the receiving server.
5. **Test Ping Dispatch:**
   - Triggers `POST /api/organizations/:orgId/webhooks/:endpointId/test` to dispatch an immediate test event verifying receiver connectivity and signature calculation.
6. **Zero Secret Exposure Guarantee:**
   - Raw secrets are never requested or exposed in GET endpoints or persistent UI state. Stored secrets remain AES-256-GCM encrypted in the database.

### 2.2 Usage & Metering Tab (`UsageAnalyticsTab.tsx`)
Connected to the existing organization usage API (`GET /api/organizations/:orgId/usage`):
1. **Auditable Metering Metrics:**
   - **Total Billed Minutes:** Displays total whole billed minutes accompanied by human-readable hours conversion (e.g. `142m (~2h 22m)`).
   - **Participant Sessions:** Total distinct join sessions recorded in the ledger.
   - **Distinct Rooms:** Count of distinct classrooms/meetings hosted within the time window.
2. **Role Breakdown:**
   - Visual proportional ratio bar comparing tutor vs student participant minutes.
   - Role cards displaying exact billed minutes and percentage per role, backed strictly by `breakdownByRole` from the ledger query.
3. **Date Range Filters:**
   - **Last 7 Days**
   - **Last 30 Days** (Backend default window)
   - **Last 90 Days**
   - **All Time** (Calculated from ledger origin)
   - Dynamic query parameters (`?startDate=...&endDate=...`) passed to the backend.
4. **State Management:**
   - **Loading State:** Centered spinner while aggregating ledger records.
   - **Empty State:** Clean educational card when 0 minutes/sessions are recorded in the selected period, showing the active query window.
   - **Error & Retry State:** Clear error notice with a "Retry" button.
5. **No Invented Billing Amounts:**
   - Strictly adheres to the requirement: displays only actual metered minutes and session counts from `organization_usage_ledger`. No arbitrary dollar charges or fictitious invoice figures are presented.

### 2.3 Integration Quickstart Tab (`QuickstartDocsTab.tsx`)
Comprehensive developer onboarding guide using actual repository packages and configuration:
1. **Active Configuration:**
   - Displays active API Base URL (`/api/v1`) and Embed Base URL with one-click copy buttons.
2. **Zero-Trust Security Architecture Callout:**
   - Prominent red alert emphasizing that **Secret API Keys must NEVER be exposed in frontend client code**.
   - Documents the short-lived participant-token flow and URL hash fragment security (`#token=...`), preventing HTTP `Referer` token leakage.
3. **SDK Installation:**
   - Copyable package installation command for `@mathsy/meet-sdk` with package manager switcher (`npm`, `pnpm`, `yarn`).
4. **Server-Side Token Flow Example:**
   - Copyable TypeScript example using `MathsyMeetServerClient` from `@mathsy/meet-sdk/server`:
     - Initializing client with secret API key.
     - Creating meeting room (`client.createMeeting`).
     - Minting short-lived participant token (`client.createParticipantToken`) with role (`tutor` | `student`) and TTL.
5. **Frontend Embedding Examples:**
   - **React:** Interactive component using `MathsyMeeting` and `MathsyMeetEmbedController` from `@mathsy/meet-sdk/react`.
   - **Plain JavaScript:** Iframe integration using `embedMeeting` from `@mathsy/meet-sdk/browser`.
   - Links to Allowed Domains tab for configuring authorized parent origins.
